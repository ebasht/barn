# Backend

Пути и команды ниже — относительно `backend/`. Go **1.25.0** указан в `go.mod`
(требование Go 1.22+ в README устарело). HTTP: chi; PostgreSQL: pgx/v5 + sqlc.

## Структура и изменения

- `cmd/server/main.go` собирает сервисы, workers, API и `/mcp`.
  `cmd/agent/main.go` — отдельный агент мониторинга хоста.
- `internal/api`: маршруты, авторизация, HTTP handlers и ответы.
  Бизнес-логика находится в `internal/<область>/service.go`, DTO в `dto.go`,
  фоновые операции в `worker.go` / `workers.go`; ориентируйся на соседний код.
- Изменение HTTP-контракта сверяй с `../frontend/lib/api.ts`, `types.ts`
  и при необходимости `normalize.ts`. JSON-имена не выводятся из Go-имён автоматически.
- Авторизация различается: API token, scoped server tokens, QR exchange и MCP key.
  Перед изменением доступа читай маршрут и его middleware, не обобщай их в один механизм.
- Docker/nginx/SSL выбирают stub или real через `factory.go` и конфигурацию.
  Для тестов используй существующие интерфейсы и заглушки.

## База данных

- Миграции goose: `migrations/NNNNN_name.sql`, секции `-- +goose Up/Down`.
  Добавляй новую миграцию, не переписывай уже выпущенные.
- `schema/schema.sql` — входная схема sqlc, `queries/*.sql` — его запросы.
  При изменении схемы синхронизируй миграцию и входную схему.
- Генерация: `sqlc generate` из `backend/` (нужен установленный sqlc;
  текущие generated headers указывают v1.29.0).
- Не редактируй вручную файлы с `Code generated by sqlc` в `internal/db`.
  Не весь каталог generated: например, `mcp_logs.go` написан вручную.
- Миграции запускаются из корня через `make migrate` и требуют Docker/БД;
  их запуск не заменяет обновление входной схемы sqlc.

## Проверки

```sh
gofmt -w <изменённые.go>
go test ./internal/<затронутый-пакет>
# Для общих контрактов или нескольких подсистем:
go test ./...
```

Не запускай сервер, установку агента или production deployment ради unit-тестов.
Не сохраняй собранные бинарники `server` и release assets в изменениях исходников.
